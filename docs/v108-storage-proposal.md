# v108 저장소·산출물 정리 제안 (실행 보류)

현재 v107의 검사 기본 경로는 이미 임시 폴더였다. 문제 재발 방지를 위해 모든 검사·촬영 진입점과 전체 실행기의 하위 프로세스에 쓰기 보호를 추가했다. `docs/validation`로의 쓰기·삭제·이름 변경은 심볼릭 링크를 거쳐도 거부한다. 읽기는 허용한다. 단독 실행과 `npm run check` 모두 적용한다. 기존 자료의 해시 목록을 외부에 기록해 전체 검사 뒤 변조가 없는지도 확인한다.

측정값(2026-11-27): 기존 검증 폴더 436파일 / 93,446,863바이트(93.45MB), 추적 파일 합계 약 281.10MB다. 앞서 언급된 243MB와 측정 범위가 다르다. Git 공통 저장소는 여러 작업 트리·브랜치를 공유하며 loose 136.93MiB + pack 114.35MiB다.

실행하지 않은 선택지는 다음과 같다.

1. **Pages 배포에서만 제외:** 배포 작업이 게임 파일만 복사하고 `docs/validation`, 검사 전용 FBX/ZIP을 생략한다. 검증 폴더만 제외하면 배포 원본이 약 93.45MB 줄고 Git 이력은 그대로다. 게임 실행에 쓰이지 않는 원본 FBX/ZIP을 추가로 제외하는 방안은 기존 v107 제안을 참고한다.
2. **과거 미디어를 별도 보관 후 현재 트리에서 제거:** PNG/MP4 등을 Releases나 별도 검증 저장소로 옮긴다. 현재 검증 미디어는 약 86.25MB이며 이를 모두 옮기면 현재 추적 트리에서 그만큼 줄어든다. 텍스트 기록과 작은 JPG를 남길 수 있다. Git 과거 이력의 용량은 줄지 않는다.
3. **이력에서도 제거:** 보관·복구 검증 후 승인된 미디어 경로 목록만 `git filter-repo`로 제거한다. 현재 브랜치 전체에서 확인한 대상 고유 미디어 blob 원본 합계는 약 86.25MB다. 실제 pack 절감량은 압축·델타·다른 참조에 따라 달라 재작성한 임시 미러에서 먼저 측정해야 한다. 커밋 해시 변경, 강제 푸시, 재클론이 필요하다.

위 세 방식의 기존 파일 삭제·이동·이력 재작성·배포 구성 변경은 아직 실행하지 않았다. 사용자 확인 후 선택한 방식만 진행한다. 새 검증 원본은 저장소 밖에 보관한다.

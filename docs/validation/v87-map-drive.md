# v87 맵·수면·고저차 주행 개선

기준은 v86 머지 커밋 `cc88b96bd30ff88ec424d97e748fecfa2d28b4b5`다. [화면 슬라이더·측정표·주행 궤적](v87-map-drive.html)에서 전후를 비교할 수 있다.

## 확인한 원인과 변경

- 집을 원형 범위 안에 무작위로 놓고 도심 배치에는 경사 한도가 없었다. 도로를 향한 앞·뒷줄 필지와 골목을 만들고, 필지는 한 번씩 검사한다. 외딴 집도 접근로 주변에 배치하고 앞문을 도로 쪽으로 돌린다. 마을 건물의 기초 높이 차이는 1.6m 이하로 제한한다.
- 나무는 서로의 간격을 검사하지 않았다. 숲의 군집 노이즈와 9개 모델 변형을 유지하면서 나무 최소 4.2m, 도로 주변 8.5m, 건물 주변 5m를 확보한다. 나무 수는 12,439 → 7,523그루다. 이 배치 변경도 렌더 수치에 포함된다.
- 호수는 실제 호숫가와 다른 큰 원판으로 그려졌다. 강 수위가 국소 최저점으로 갑자기 내려가며 하류 호수 수위도 덮어썼고, 호수 내부에도 강둑이 쌓였다. 호수 입출구 사이의 연속 종단면, 선분 기준 강바닥, 지형·수역 경계에서 잘라 낸 통합 수면으로 바꿨다. 물가의 낮은 땅에 고립된 수면을 만들지 않으며 얕은 물·물가 거품을 구분한다.
- 물리 수위의 사각 보간과 지형·수면 삼각형 보간이 달랐다. 같은 삼각형을 사용한다. 마른 물가에는 지면 아래 참고 수위를 유지해 모래·식생 완충 구간을 만들되, 수역 밖의 낮은 지형을 물속으로 판정하지 않는다.
- 1536px 지형에서 512px 풀 마스크를 만들 때 2px 간격으로 써서 행이 겹쳤다. 3px 간격으로 고쳤다.
- 차량 높이는 지면으로 보간될 뿐 수직 속도가 없었다. 차체 끝을 먼저 읽어 절벽 직전에 위로 튀는 문제도 있었다. 실제 네 바퀴 위치를 읽고 자세 변화 속도를 제한한다. 접지·서스펜션 이동·공중 낙하·착지를 구분하고 9.81m/s² 중력과 최대 1/120초 간격을 적용한다.
- 공중에서 가속·지상 접지력으로 궤적을 바꾸지 않는다. 바퀴 굴림은 마지막 회전 속도를 유지한다. 상판·연석의 위치 보정을 과도한 상승 속도로 바꾸지 않도록 감쇠한다. 착지 충격·짧은 먼지·자세 복귀를 적용하고, 강한 착지는 차체에 피해를 준다. 공중 하차 뒤에도 차량이 낙하한다.
- 다리 상판 밑에 남은 산비탈을 정리하고, 상판을 지지면으로 읽으며 다리 위를 물속으로 판정하지 않는다. 경사 판정·주행·하차·타이어 자국에 같은 받침을 사용한다. 다리 아래의 차를 상판 위로 올리지 않는다.

## 렌더·검색 비용

같은 도시·숲·호숫가 좌표, **640×360·장면 해상도 100%**, Chromium / Three.js r160 / **SwiftShader 소프트웨어 렌더러**를 사용했다. 각 조건에서 두 번 준비 렌더 후, 그림자를 매 프레임 갱신하며 다섯 프레임을 측정했다. 브라우저의 `gl.finish()`만으로 완료를 가정하지 않고 1픽셀을 읽어 GPU 작업을 기다렸다.

다음 표는 각 장면의 프레임 중앙값을 세 장면 사이에서 평균한 값이다. **하드웨어 GPU의 실제 FPS나 이용자의 주관적 체감 비율로 환산할 수 없다.**

| 품질 | v86 동기 렌더(ms) | v87 동기 렌더(ms) | 시간 변화 |
| --- | ---: | ---: | --- |
| 최저 | 750.9 | 662.2 | 11.8% 감소 |
| 낮음 | 1635.5 | 1422.0 | 13.1% 감소 |
| 중간 | 2893.2 | 2400.8 | 17.0% 감소 |
| 높음 | 4389.1 | 3447.1 | 21.5% 감소 |

식생 목록 갱신 비용의 12조건 중앙값은 **0.216 → 0.038ms (82.6% 감소)**였다. 고정 카메라에서 강제로 갱신한 16회 묶음 7개의 중앙값을 조건별로 구했다. 가까운 나무는 64m 격자에서 찾고, 먼 사진판은 여유 있는 시야 범위만 제출하며 이동·회전 시 목록을 재사용한다. 시야 안 나무가 누락되지 않는지 별도 검사했다. 도로 거리의 보수적 하한 캐시는 263,169바이트다.

나무·건물 배치 변경, 검색, 제출 최적화가 함께 반영된 결과다. 수면은 정확한 해안선을 위해 1,030 → 16,538개 삼각형으로 늘었고, 호수·강은 통합한 한 메시로 제출한다. 매 프레임 새 수면 지오메트리나 후처리를 만들지 않는다. 정적 음영 406개 청크를 다시 구웠으며 거부된 청크는 0개다.

## 주행 수치와 영상

같은 20m 낙차·초기 속도 15m/s·60Hz·가속 페달을 놓은 조건에서, 위치로 역산한 최대 하향 가속도는 **2139.43 → 22.18m/s²**였다. 개선 후 체공 시간은 1.85초였다. 완만한 20% 내리막에서 6초 뒤 속도는 0.00 → 5.96m/s로, 지면에 끌려 붙던 감속을 줄였다.

실사 3종·기본 대체 차량을 30·60·144FPS로 검사했다. 공중 중력 오차는 0.001m/s² 미만, 착지는 한 번씩 발생했다. 평평한 절벽에서 출발 높이보다 4cm 이상 솟는 경우는 없었다. 프레임률 간 착지 시각 차이는 최대 0.021초였다. 다리 3곳의 실제 상판·난간을 포함한 주행과 하부에서 상판 위로 올리지 않는 지지면 판정도 검사했다.

[5초 주행 영상](v87-downhill.webm)은 **12m 실험 지형**, 실제 운전 입력·추적 카메라·60Hz 시뮬레이션을 12fps로 고정 캡처했다. 실시간 FPS 측정 영상은 아니다. [체공 화면](v87-airborne.png) · [착지 화면](v87-landing.png).

## 재현

기존 Playwright·Three.js r160·Chromium 환경을 사용한다. 영상에는 ffmpeg가 필요하다. 비교 실행은 기준 커밋의 Git 이력이 필요하다.

```sh
node tools/check-map-hydrology.cjs --compare
node tools/check-map-drive.cjs
MAP_FALLBACK=1 node tools/check-map-drive.cjs
node tools/check-vehicle-wheels.cjs
node tools/check-training-range.cjs
node tools/check-vehicle-throwable-vfx.cjs
node tools/check-startup.cjs
node tools/bench-map-drive.cjs before /tmp/lz-v87
node tools/bench-map-drive.cjs after /tmp/lz-v87
node tools/capture-map-drive.cjs /tmp/lz-v87-drive
```

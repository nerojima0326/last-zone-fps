# v78 — 화질·로딩·메모리 최적화

## 적용 내용

1. **1인칭 선명도 분리.** 배경이 화면보다 낮은 해상도일 때 배경 후처리·업스케일 뒤에 총과 손을 화면 해상도로 합성합니다. 조준 카메라·기준점·애니메이션 계산은 그대로 사용합니다. 투명 영역은 즉시 건너뛰고, 기존 색보정을 사용합니다. 배경 해상도가 충분하면 기존 단일 composer 경로를 사용하고 별도 타깃을 해제합니다. 화면 크기 변경·메뉴 복귀·품질 변경도 처리합니다. 블룸은 배경 경로에 남으며 1인칭 섬광은 기존 재질로 표시됩니다.
2. **총기 30종 실제 메시 LOD.** 12m·28m용 단순화 메시 60개를 공유 파일에 넣었습니다. 기존 총기 재질 병합에 더해 실제 정점·삼각형 수를 줄입니다. 확대 조준과 전환 여유 거리를 반영하고, 가까이에서는 원래 모델을 사용합니다. 다른 플레이어와 바닥 전리품에 적용됩니다. 정규화된 양자화 속성은 월드 변환 전에 float으로 풉니다.
3. **1인칭 모델 지연 생성·장전 팩 요청 로딩.** 메뉴에서는 M4/Glock 가져오기에 필요한 두 기본 총과 주먹·투척 모델만 만듭니다. 시작 장비는 매치 준비 때 생성·컴파일합니다. 교체할 장비의 팩도 미리 요청하며, 같은 팩·교체 모델의 중복 다운로드를 합칩니다. 조준·장전 중에 도착한 팩은 동작이 끝난 후 활성화합니다. 월드 전리품과 도감에 필요한 기본 총기 데이터는 계속 공유 로딩합니다. 전체 모델이나 텍스처를 전부 지연 로딩했다고 주장하지 않습니다.
4. **고정 주변 음영.** 건물·가구 주변에 짧은 반구 방향 광선을 쏘아 정점별 주변 가시성을 미리 계산했습니다. 간접광에만 적용하며 런타임 화면 전체 음영 패스나 광선 계산은 추가하지 않습니다. 배치에 남아 있던 무작위 선택을 고정된 전용 난수로 바꾸어 베이크를 재현합니다. 청크별 정점 수·위치 해시가 맞는 경우에만 적용하며 오래되거나 손상된 데이터는 생략합니다. 시간대별 태양·움직이는 대상의 그림자는 기존 품질별 경로를 사용합니다.
5. **KTX2 GPU 압축.** 지형·건물 텍스처 42장을 변환했습니다. 실제 게임은 이 중 39장을 사용합니다. 노멀은 UASTC, 색과 ARM은 ETC1S를 사용하고 밉맵·색공간·업로드 방향을 유지합니다. 지원되는 GPU 형식이 없거나 다운로드·변환이 실패하면 각 텍스처의 기존 JPEG로 돌아갑니다. 로딩 후 변환 작업자는 정리합니다.

## 측정 결과와 한계

환경: Chromium 156 / Three.js r160 / ANGLE SwiftShader 소프트웨어 렌더러. 아래 수치는 이 환경의 자원·구조 검증이며 사용자의 실제 GPU FPS 예측이 아닙니다.

| 항목 | 기존 경로 | v78 |
| --- | ---: | ---: |
| 메뉴에서 생성한 1인칭 모델 | 32개 | 4개 |
| 메뉴에서 자동 요청하는 일반 장전 팩 | 8개 | 0개 |
| 기본 훈련 장비 준비 후 1인칭 모델 | 32개 | 6개 |
| 사용한 월드 텍스처 39장의 밉 데이터 | 비압축 RGBA 환산 218,103,808바이트 | 관측된 압축 데이터 54,526,992바이트 |
| 변환한 42장 합계 다운로드 파일 크기 | JPEG 27,620,422바이트 | KTX2 23,052,345바이트 |
| 30종 총기 삼각형 합계 | 340,223 | 중거리 78,527 / 원거리 22,240 |
| 같은 30종을 전리품 재질로 그릴 때 draw calls | 127 | 중·원거리 각 30 |
| 같은 30종을 손에 든 재질로 그릴 때 draw calls | 60 | 중·원거리 각 30 |

- 압축 데이터 수치는 해당 39장만의 합계입니다. 드라이버 관리 메모리·나머지 총기·렌더 타깃 등 전체 VRAM 사용량을 뜻하지 않습니다. GPU가 선택하는 형식에 따라 달라집니다.
- 같은 훈련장 짝 비교에서 소프트웨어 렌더링 중앙값은 공유 해상도 424.9ms, 별도 1인칭 426.9ms였습니다. 이 느린 소프트웨어 환경의 절대 시간은 실제 GPU 성능을 뜻하지 않습니다. 화면 비교의 F3 값은 일시정지·수동 렌더링의 누적 값이므로 FPS 비교에 사용하지 않습니다.
- 1인칭 선명도 분리는 낮은 해상도의 총을 더 많은 픽셀로 그리므로 추가 비용이 있습니다. 합성 1회와 필요할 때만 할당하는 HDR 타깃이 추가됩니다. 배경 해상도가 충분하면 사용하지 않습니다.
- 단순화 메시에서 원거리 삼각형 수는 합계 약 93.5% 줄었습니다. 전체 프레임 시간이나 전체 장면의 삼각형이 같은 비율로 감소한다는 뜻은 아닙니다.
- 고정 음영은 394개 청크에 적용됩니다. 지오메트리를 변경하면 재생성해야 하며, 불일치하는 청크는 밝은 기본 주변광을 유지합니다.
- 이전 전체 장면 벤치마크와 새 월드를 직접 비교해 FPS 향상률을 계산하지 않았습니다. 같은 페이지·같은 장면의 짝 비교를 사용합니다. 실제 하드웨어에서는 `F3`의 CPU/GPU 시간과 1% low로 숲·도시·교전 장면을 재측정해야 합니다.

## 검증

아래 9개 검사 모두 통과했습니다. 브라우저 오류는 없었습니다. 조준 166개 조합·7,128개 샘플, 손 자세 810개·반복 동작 60개, 장전 간섭 180개·32,334개 프레임을 확인했습니다.

- `tools/check-quality-performance.cjs`: 30종 LOD의 실제 삼각형 감소·크기·거리·확대 조준 전환, 초기 생성 수, 장비별 팩 요청 수, GPU 압축 로딩, 베이크 해시 일치, 화면 해상도 합성, 배경 보존, 창 크기 변경, 사용하지 않는 HDR 타깃 해제, 조준·장전 중 활성화 지연, 중복 요청 방지, KTX2 실패 시 JPEG, 잘못된 베이크·누락된 LOD·누락된 장전 팩의 대체 동작.
- `tools/check-aim.cjs`: 실제 마우스로 10m·50m·100m 표적 명중, 30종·조준기·동작·화면 비율·30/60/144 FPS에서 조준 정렬 및 반동.
- `tools/check-reloads.cjs`: 60개 장전 사례, 20,857개 프레임, 탄 수·소리 720개 사례.
- `tools/check-hand-poses.cjs`, `tools/check-clearance.cjs`: 30종 손 자세와 반복 동작, 빈 총·전술 장전 간섭.
- `tools/check-bundled-viewmodels.cjs`: 기본·실사·누락된 에셋 경로, 파일 선택 없이 동작, 캐시 버전과 재접속.
- `tools/check-training-range.cjs`: 사격장·충돌·표적·전리품·차량·다시 시작·정리.
- `tools/check-weapon-catalog.cjs`: 도감·검색·모바일 배치·신규 15종 장비·매치 제한·정리.
- `tools/check-weapon-audio.cjs`: 30종 총성·장전 이벤트와 대체 재생.

전체 모델을 검사하는 기존 도구는 검사 준비 단계에서 `VM.ensure`와 `AssetVM.loadAll()`을 명시적으로 호출하도록 바꿨습니다. 게임의 일반 시작 경로는 전체 팩을 미리 받지 않습니다.

## 재생성·실행

런타임은 계속 정적 파일로 실행됩니다. 새 빌드 단계가 필요하지 않습니다. 선택적인 개발 도구의 의존성은 Playwright, Three.js 0.160.0, @gltf-transform/core/extensions/functions 4.4.1, meshoptimizer 0.23, Sharp 0.34.5입니다.

```bash
# 호환 Chromium이 이미 있으면 사용합니다. THREE_DIR은 CDN 모듈의 로컬 경로입니다.
export CHROME_BIN=/usr/bin/chromium
export THREE_DIR=/path/to/node_modules/three
# 필요한 개발 패키지를 설치한 폴더를 NODE_PATH로 지정합니다.
node tools/optimize/build-weapon-lods.cjs
node tools/optimize/bake-static-ao.cjs
# basisu npm 1.16.3의 Linux x64 인코더 (표시 버전 v1.15)
BASISU=/path/to/basisu node tools/optimize/build-gpu-textures.cjs
REPORT=/tmp/quality.json node tools/check-quality-performance.cjs
node tools/bench-quality.cjs /tmp/quality-bench
```

`build-gpu-textures.cjs`는 이미 생성한 파일을 재사용합니다. 원본이나 인코딩 설정을 바꿨으면 해당 KTX2를 지우고 재생성합니다. 강제로 JPEG 경로를 시험하려면 `?textures=jpeg`를 사용합니다. `F3`에는 배경·화면·총/손의 해상도가 표시됩니다. `G.renderFeatures.nativeViewmodel`은 동일 장면 짝 비교용 진단 스위치입니다.

# v83 플레이 품질·훈련 기록

기준은 v82 머지 커밋 `a758fec49ba8265ab02b14da5963a40300bab735`이다. 2026년 11월 23일 Chromium 156 / Three.js r160 / ANGLE SwiftShader에서 검사했다.

## 확인한 원인과 변경

### 순간 끊김

- 기존 입자는 발사·폭발마다 새 객체를 만들었다. 수명이 끝난 객체를 반환하고 다음 생성에 재사용한다. 활성 입자와 보관 입자의 합은 기존 표시 한도를 넘지 않는다. 속도·색·중력·바닥·수명을 모두 초기화한다.
- 시작 셰이더 준비가 기본 프레임버퍼를 기준으로 진행돼 실제 HDR 합성 경로에서 다른 셰이더가 필요했다. 월드와 총기를 각각 실제 렌더 타깃의 출력 조건으로 준비한다.
- 늦게 받은 총기 팩은 텍스처 업로드와 셰이더 준비를 마친 뒤 사용할 수 있다. 준비 중에는 기존 기본 모델을 유지하며, 조준·사격·장전 중에는 준비를 미룬다. 텍스처는 콜백마다 한 장씩 올린다. 장전 취소 후 자세 복귀가 끝나기 전에도 팩을 교체하지 않는다.

| 같은 입력의 검사 | v82 | v83 |
| --- | ---: | ---: |
| 입자 64개 × 100회에서 사용한 객체, 가산/일반 각각 | 6,400개 | 64개 |
| 늦게 받은 SC-17을 처음 표시하며 추가한 셰이더 프로그램 | 3개 | 1개 |

사용한 입자 객체는 **99% 감소**했다. SC-17은 표시 전에 프로그램 2개를 준비한다. 셰이더를 준비하는 비용 자체가 사라지는 것은 아니며, 아직 준비하지 않은 부착물 등의 첫 표시 비용은 남을 수 있다.

[전후 원시 측정](v83-session-benchmark.json)은 `tools/bench-session-polish.cjs`로 v82 HTML·전체 JS를 고정해 비교했다. 첫 렌더 시간은 각각 한 번의 콜드 측정과 두 번의 후속 프레임이므로 참고용이다. 이 환경에는 실제 GPU가 없어 일반 PC의 FPS 향상률·1% 하위 FPS 개선률로 환산하지 않았다. 기능 검사의 인위적인 프레임 간격도 실측 FPS가 아니다.

### 실제 PC 성능 기록

설정의 **플레이 성능 기록 → 성능 기록 시작**을 누르고 설정을 닫아 플레이한다. 다시 설정을 열어 종료하거나, 활성 플레이 시간 60초가 되면 자동 종료한다. **기록 저장**으로 JSON을 내려받는다. 메뉴·일시정지·다른 탭의 시간과 복귀 첫 간격은 제외한다.

평균 FPS, 가장 느린 1% 프레임들의 평균 간격을 FPS로 바꾼 값, 최장 프레임, 품질·해상도·렌더러, 전체 프레임 간격을 담는다. 50ms 초과 프레임에는 업데이트·렌더 제출 시간과 500ms 이내의 발사·장전·교체·폭발·지역 진입 동작을 기록한다. 이 시간은 CPU 제출 시간이며 GPU 완료 시간이 아니다. 가까운 동작은 끊김의 원인으로 확정한 값이 아니다. 프레임 18,000개·동작 120개·긴 프레임 80개로 메모리를 제한하며 외부 전송 없이 사용자가 내려받는다.

### 총기 전환

- Glock의 달리기 자세가 입력의 참/거짓에 따라 즉시 바뀌던 부분을 기존 감쇠값으로 연결한다.
- 기본 모델·M4·Glock·추가 팩 모두 완전 조준에서 달리기의 잔여 자세를 제거한다.
- 무기 교체는 현재 내려간 높이에서 시작하고, 내려가기·올라오기에 완만한 곡선을 사용한다. 교체 시간 0.46초와 0.2초의 숨겨진 슬롯 교체 시점은 유지한다.
- 장전 종료·취소 후 기존 장전 곡선의 복귀 구간을 0.13초 동안 재생한다. 관절을 따로 보간하면 여러 총기에서 손바닥이 총을 관통하는 문제가 검사에서 확인돼, 기존 손 접촉 보정을 매 프레임 거치는 방식으로 바꿨다. 완전 조준·발사·무기 변경 시에는 해당 동작을 우선하며 탄약 지급·발사 시각·카메라 조준점을 바꾸지 않는다.

### 봇

같은 적도 0.35초 이상 가려졌다가 다시 보이면 짧게 재조준한다. 보이지 않는 동안 반응 대기를 소모하지 않는다. 매 프레임 작은 난수를 더하던 조준 오차를 시간·거리·이동에 따른 지속 오차로 바꿔 장시간 추적 후 완벽히 수렴하거나 프레임 수에 따라 달라지는 현상을 줄인다. 아군의 기존 난이도 프로필은 유지한다.

엄폐 도착 지점이 다른 충돌체 안이면 제외하고, 적의 실제 가슴 높이까지 가려지는지 확인한다. 기존 경로 검사·좌우 벽 회피·엄폐 도착 후 대기 동작을 유지한다.

### HUD

### 훈련 기록

메뉴·훈련장 상단·일시정지의 **훈련 기록**에서 시작한다. 선택한 10 / 25 / 50 / 100m 사격선으로 이동하고 현재 탄창과 표적을 초기화한다. 30초 동안 정면의 지정 표적만 집계한다. 산탄은 발사 한 번당 한 명중·한 헤드샷으로 집계한다. 처치 시간은 첫 명중부터 표적이 쓰러질 때까지이며 한 발 처치는 0초가 가능하다.

명중률·헤드샷 비율·처치 수·평균 처치 시간을 같은 총·거리의 최근·이전·최고 기록과 비교한다. 최고 기록은 처치 수 → 명중률 → 처치 시간 순이다. 부착물은 강제로 맞추지 않으므로 부착물의 영향도 결과에 포함된다. 기록 60개를 브라우저에 보관하고 최근 10개를 표시한다. 손상된 저장 데이터는 걸러내며 저장이 차단되면 실행 중 메모리에서 사용할 수 있다.

일시정지·탭 전환은 측정 시간에서 제외한다. 1.5m 초과 이동·총기 변경·차량·투척·훈련 종료 시 중단하며 부분 기록은 저장하지 않는다. 사격하지 않은 측정도 저장하지 않는다.

[기록 비교 화면](v83-records.png)은 비교 문구·배치를 검사하기 위한 예시 데이터를 표시한 화면이다.

총기 30종의 **1,980개 자세·반복 전환 60개**에서 실패가 없었다. 달리기→조준과 장전 취소 후 손 접촉은 30·60·144 FPS에서 검사했다. 빠른 복귀 때는 손목의 추가 지연을 제거하고 자유 손이 총몸 바깥으로 돌아오게 한다. MG-60은 넓은 급탄부를 피하는 옆 경로도 적용했다.

훈련 기록 검사는 4개 거리의 실제 탄도 명중, 30초 이후 집계 제외, 일시정지, 산탄 중복, 저장 손상·차단, 재접속 후 기록, 실제 JSON 다운로드와 훈련장 재입장 2회까지 통과했다. 조준·반동, 시작 로딩·에셋 복구, 화질·네이티브 레티클, 봇 이동, 장전·탄약·음향, 장전 간섭, 훈련장 일반 생명주기 검사도 통과했다.

Playwright·Three.js·Chromium 경로는 기존 `NODE_PATH`, `THREE_DIR`, `CHROME_BIN`을 사용한다. 새 통합 검사를 CI에 연결했다. [통합 검사 결과](v83-session-checks.json) · [손 형상 측정](v83-hand-checks.json) · [실행한 검사 목록](v83-checks.json) · [화면 경계값](v83-hud-bounds.json).

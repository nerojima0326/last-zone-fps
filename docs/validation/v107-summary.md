# v107 수정·검증 요약

기준 main: `b375107` (v106). 요청 항목별 커밋 6개 뒤에 빌드 번호와 이 보고서를 반영했다. 실행 결과는 [전체 검사 표](v107-checks.md)와 [명령·로그 목록](v107-checks.json)에 기록했다.

## 재현한 원인과 결과

- 장전: 탄창을 놓은 뒤 손목을 돌리는 구간에 측면 탈출 경로가 없었다. 여섯 총기의 경유점과 SR25 빈 총 장전의 자유 손 경로를 수정했다. 180조합·32,334프레임에서 기준 초과 14건 → 0건. 작동 3mm·복귀 10mm 기준은 유지했으며 수정 후 전체 최대는 작동 0mm·복귀 9.9738mm였다.
- 차량: 머리만 축소한 상태에서 카메라에 걸리는 몸통 면이 남았다. 내부 시점에서는 팔 삼각형만 그리고 외부 시점·하차에서 원본 몸 전체를 복원한다. 4종·5리그×3조향, 반복 탑승의 자원 증가 0을 확인했다. 모바일 검사도 통과했다.
- AR-7: 정상적인 압축 법선의 4바이트 간격을 가늠자 분리 코드가 3바이트씩 읽었다. 본체 법선 9,960개가 잘못되고 1,546개가 0벡터가 됐다. stride·offset을 보존한 뒤 위치·법선·UV 23,898개가 원본과 모두 일치했다. 실제 표시 메시 전체 30정의 비정상 법선도 0개다. 재질·접선·필터 대조 결과는 [원인 보고서](v107-03-surface.md)에 있다.
- 캐릭터 도구: 필요한 `airborne.js`를 게임처럼 준비하도록 수정했다. 2종·7자세·60장전 조합과 다른 도구 페이지를 확인했다.

## 실시간 최종 재검사

Linux Chromium·SwiftShader, 320×180·최저 품질·DRS 자동. 아래 수치는 클라우드 소프트웨어 렌더러의 기록이다. 실제 휴대폰 FPS로 환산하지 않는다. 프레임 dt 상한 때문에 실제 시간과 게임 시간은 다르며, 수동 시간 전진·일시정지는 사용하지 않았다.

|---|---:|---:|

첫 렌더 콜백 종료 시각과 GPU의 실제 표시 시각은 구분한다. 경기에서는 수송기→자유낙하→낙하산→착지를 실제 입력·물리 경로로 확인했다. JS 힙·ArrayBuffer 등 backing storage·렌더러 RSS를 분리해 기록했다. 새 계측 스크립트의 변수명 충돌을 수정한 뒤 재실행한 결과다.

warmup 대상은 뷰모델 6개였으며 텍스처는 이미 프레임별 대기열로 준비하고 있었다. 시작 장면 구성과 현재 장비의 셰이더를 우선 준비하고 나머지를 2~4ms 단위로 나누는 후속 구현안은 [검사 환경·시작 비용 보고서](v107-05-environment.md)에 제시했다.

## 화면과 대용량 자료

1~3번은 동일 조건의 전후 실제 게임 화면을 저장했다. 장전 6종과 SR25 빈 총 장전, 차량 4종 내외부·실제 훈련장, AR-7의 1280×720·1920×1080 원본을 포함한다. 비교 화면 19쌍과 겹침 슬라이더는 `/workspace/artifacts/v107/comparisons/index.html`에 있고, 원본 PNG·로그도 같은 외부 산출물 폴더에 있다. 저장소에는 새 큰 이미지·영상을 추가하지 않았다.

기존 대용량 파일 삭제와 main 히스토리 정리는 실행하지 않았다. 두 원본 모델의 검사·변환 용도, 약 123.06MiB의 배포 제외안, 일반 삭제와 히스토리 정리의 차이는 [용량 정리 제안](v107-06-storage-proposal.md)에 기록했다. 실제 배포 변경과 삭제는 사용자가 방법을 확인한 뒤 진행한다.

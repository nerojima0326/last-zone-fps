# v84 차량 내구도·총기 사운드·투척 효과

기준은 v83 머지 커밋 `83563f6eecc062ca3b4f07196f51840a19434bf2`이다. Chromium 156 / Three.js r160 / ANGLE SwiftShader에서 실제 게임·오프라인 오디오 믹서·전후 화면을 검사했다.

## 차량 내구도 5배

공통 최대 내구도가 320이어서 차종과 관계없이 비교적 적은 피탄으로 화재가 시작됐다. 포터·E2200·IZH와 모델 누락 시 사용하는 기본 차량의 내구도를 **1,600**으로 올렸다. 연기 발생·출력 저하·봇의 탑승 판단·내구도 표시도 같은 최대값을 기준으로 하므로 비율이 유지된다.

실제 탄도 검사에서 세 차종 모두 근거리 AR-7 탄 **84발**에 화재가 시작됐고, 차량이 수류탄의 최대 피해 230을 받는 조건에서는 **7회**가 필요했다. 총알의 차량 피해 배율 0.8과 수류탄의 최대 차량 피해 230은 바꾸지 않았다. 소총으로 내구도를 소진하면 기존 2.4초 화재 뒤에 폭발하며, 폭발 피해로 소진된 경우의 짧은 화재 지연도 유지한다.

실제 파괴·재생성을 거친 세 차종 모두 내구도 1,600으로 돌아왔다. 탑승자 충돌 피해·차량 속도·수류탄 대인 피해·차량 폭발의 대인 피해는 변경하지 않았다.

## 총기 30종의 새 사운드

- 30종 모두 압력파 생성 방식과 음색 표를 바꿨다. 짧은 파열음, 독립적인 저음 몸통, 가스 배출, 약실 공명과 공간 반사를 조합하고 이전의 강한 포화를 줄였다. 기존 발사 PCM을 새 총성의 입력으로 사용하지 않는다.
- 총별 네 발사 변형과 근거리·원거리, **180개 총성**을 `*-report-v84.mp3` 30개로 교체했다. 저격총·대구경·산탄총·기관단총·권총에 서로 다른 대역 비중·감쇠·반사를 사용한다.
- CC0 조작음 원본을 고정된 v83 커밋에서 읽고 총별 EQ·접촉 공명층·무게감을 더했다. 공유하던 조작음을 독립적인 `*-handling-v84.mp3` **30개**로 교체했다. 생성 결과를 다시 가공하지 않으므로 반복 재생성해도 같은 파일을 만든다.
- 장전 사건 시각과 탄약 지급은 그대로다. 연사 꼬리 감쇠·최대 동시 발사음·소음기·원거리 감쇠·음속 지연·음소거·오디오 노드 정리를 검사했다. 새 파일이 없거나 이전 매니페스트가 남으면 같은 v84 생성기로 새 총성을 만든다.

[총성·조작음 비교와 30종 선택 듣기](v84-audio.html) · [총성 이전→이후](v84-report-comparison.mp3) · [탄창·탄 삽입음 이전→이후](v84-handling-comparison.mp3) · [30종 새 총성](v84-all-weapon-reports.mp3)

전후 비교는 AR-7 → KA-47 → MG-60 → KR-98 → S-12 → P-226 순이며 총별로 이전, 이후를 차례로 재생한다. 총성 비교 파일은 생성 원본을 같은 배율로 재생한 자료다. 실제 게임 압축기·음량·공간 음향은 별도의 믹서 검사에서 확인했다.

이전과 새 총성의 저·중·고 대역 비중과 6ms·25ms의 초반 에너지 분포가 **30종 모두 변경**됐음을 검사했다. 이 수치는 음색 변화 확인을 위한 수학적 검사이며 사람의 청취 평가나 실총 녹음과의 일치율을 뜻하지 않는다. [대역·포락선 비교·재생 순서](v84-audio-comparison.json).

실제로 요청하는 고유 오디오 파일 합계는 **4,107,556 → 3,783,570바이트, 약 7.9% 감소**했다. 조작음에서 사용하지 않는 과거 발사 구간을 제외하고 큐를 다시 묶었다. 고유 다운로드·디코딩 파일은 46개에서 61개로 늘지만 전체 바이트는 줄었다. 매니페스트의 파일명·내용 해시·판본을 함께 바꿔 새 파일을 사용하도록 했다. 재생성한 60개 총성·조작 뱅크와 매니페스트가 배포 파일과 동일한 것도 확인했다.

## 수류탄·화염병 효과

기존 수류탄은 큰 부드러운 점 입자를 겹쳐 긴 불덩이를 만들고, 화염병 불꽃도 같은 점 입자를 사용했다. 또한 화염병의 충돌 분기는 투척 목록만 제거해 병 모델이 장면에 남을 수 있었다.

- 수류탄은 0.1초 안팎의 섬광·짧은 가스 분출 뒤에 어두운 연기, 지면의 흙먼지, 빠른 고체 파편과 그을음으로 이어진다. 지면에서 떨어진 공중 폭발에는 바닥 먼지 고리를 붙이지 않는다.
- 화염병은 충돌 순간 병을 제거하고 초록·갈색의 입체 파편을 뿌린다. 연료가 퍼진 바닥에서 움직이는 불길·검은 연기·작은 불티가 나오고 그을음이 남는다. 불꽃은 절차적으로 만든 16칸 아틀라스와 국소 UV 움직임을 사용한다. 화면 전체 왜곡이나 흐림을 추가하지 않는다.
- 파편은 중력·회전·바닥 반사·벽 충돌을 사용한다. 충돌 검사를 건너뛴 경우에도 이전 검사 위치부터 선분을 확인한다. 지면 높이는 제한된 예산으로 갱신한다.
- 폭발 처리는 중복 호출해도 한 번만 적용한다. 연막탄은 기존 분사 모델을 유지하며 나머지 투척 모델은 폭발 시 제거한다.
- 수류탄 대인 피해·폭발 반경과 화염병의 3.4m 판정·9초 지속 시간은 유지한다.

## 성능과 검증

전용 렌더는 불꽃·연기, 고체 파편, 바닥 효과의 **3개 인스턴스 메시**다. 512×512 아틀라스를 미리 업로드하고 파편의 인스턴스 색도 초기화해 첫 사용의 준비 비용을 줄인다. 조명은 기존 2개 풀을 사용한다.

| 품질 | 최대 불꽃·연기·불티 | 최대 입체 파편 |
| --- | ---: | ---: |
| 최저 | 80 | 24 |
| 낮음 | 128 | 48 |
| 중간 | 192 | 72 |
| 높음 | 256 | 96 |

바닥 효과는 최대 48개이며 가까운 화염 6곳까지 세부 입자를 낸다. 화면 거리와 기존 품질 단계에 따라 밀도를 줄인다. 피해 판정은 표시 개수 제한과 분리된다.

폭발·화염병 **30쌍**을 반복해도 장면 객체·GPU 지오메트리·텍스처의 증가가 각각 0이었고, 정리 후 활성 효과 0·재사용 슬롯 256개로 돌아왔다. 30·60·144 FPS의 화염 생성량, 품질 네 단계, 기존 효과 복귀, 실제 화염병 충돌·중복 폭발 방지와 병 모델 제거를 검사했다.

같은 800×450·중간 품질·100% 렌더 해상도 장면에서 전후 화면을 저장했다. 이 비교의 전체 드로 수는 140회에서 시점별 140~142회로 바뀌었다. [화면·드로 수 원시 자료](v84-vfx-comparison.json)의 렌더 시간은 소프트웨어 렌더러의 단일 프레임 참고값이며 다른 검사와 동시에 실행된 구간도 있다. 실제 GPU의 FPS 향상률·저하율로 해석하지 않는다.

[차량·충돌·풀·프레임률 검사](v84-vehicle-vfx-checks.json) · [실제 오디오 믹서](v84-audio-checks.json) · [실행한 검사 목록](v84-checks.json). 실제 오디오 믹서의 30종 발사·장전·연사·대체 총성·소음기·음소거·큐 경계·노드 정리, 시작 로딩과 에셋 복구, 네이티브 레티클, 훈련장 재입장·전투·부착물 동작이 통과했다. 전투 검사의 표적은 가슴 위치를 제공하는 실제 Actor로 갱신해 v83 엄폐 판정 계약에 맞췄다.

## 재현

```sh
node tools/build-original-weapon-audio.cjs
node tools/check-original-weapon-audio.cjs
node tools/check-weapon-audio.cjs
node tools/check-vehicle-throwable-vfx.cjs
node tools/compare-weapon-audio-v84.cjs /tmp/lz-v84-audio
node tools/capture-throwable-vfx.cjs before /tmp/lz-v84-vfx
node tools/capture-throwable-vfx.cjs after /tmp/lz-v84-vfx
VFX_CLOSE=1 node tools/capture-throwable-vfx.cjs after /tmp/lz-v84-close
```

기존 `NODE_PATH`, `THREE_DIR`, `CHROME_BIN` 설정과 ffmpeg를 사용한다. 오디오 재생성과 이전 소스 비교에는 기준 커밋이 필요하다. 새 차량·투척 효과 검사를 CI에 추가했다.

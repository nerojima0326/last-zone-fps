# v82 시작 로딩 개선

기준은 v81 머지 커밋 `fd69227425cc4db76f520d2fc11e5678788c0f48`이다. 로딩 순서를 먼저 브라우저에서 측정한 뒤, 서로 독립적인 다운로드·에셋 준비를 겹쳤다. 모델·텍스처·맵을 생략하거나 게임 시작 버튼을 누른 뒤로 옮기지 않았다.

## 확인한 병목

첫 측정에서 메뉴 준비까지 13.65초, GPU가 첫 게임 화면을 완성할 때까지 18.40초였다. 이 환경은 Chromium 156 / ANGLE SwiftShader 소프트웨어 렌더러다.

- Three.js 부가 모듈 14개를 순차적으로 import하고, 게임 스크립트 55개도 앞 파일이 준비된 뒤 다음 요청을 보냈다. 네트워크 왕복 지연이 누적되는 구조였다.
- 월드 초기화가 텍스처·AO → 훈련장 시설 → 군인 → 총기·원거리 모델 → 부착물을 차례로 기다렸다. 첫 측정의 텍스처 준비는 약 2.52초, 총기 준비는 약 2.63초였으며 서로 겹치지 않았다.
- 차량·투척물·장전 데이터와 M4·Glock 파일 해석도 월드가 완성된 뒤 시작했다.
- 첫 화면의 GPU 처리 시간도 별도로 컸다. 로딩 창을 일찍 숨기는 것으로 이 비용을 감추지 않고, 메뉴 준비와 실제 첫 화면 완료를 각각 측정했다.

## 변경

- 브라우저의 모듈 캐시를 유지하면서 Three.js 부가 모듈을 함께 요청한다. 나무 생성기 모듈도 게임 스크립트 준비와 겹친다.
- 게임 스크립트는 `preload`로 내려받고 기존 순서로 실행한다. 필수 파일이 실패하면 그 지점에서 실행을 멈추므로 뒤 파일의 연쇄 오류를 방지한다. 측정에서 55개 모두 한 번씩만 요청됐다.
- 독립적인 월드 에셋들을 함께 준비한다. 필요한 에셋이 준비된 뒤 지형·건물·식생을 생성한다. 월드의 난수 시드·생성 순서는 유지한다.
- 차량·투척물·장전 데이터를 맵 생성과 함께 준비한다. M4·Glock은 파일 해석만 먼저 진행하며, VM 설치·후크 연결·사용자 ZIP 복원은 기존 순서로 유지한다. 먼저 읽은 모델 Promise를 재사용해 중복 요청을 막는다.
- HDR 하늘과 배경 이미지를 함께 내려받는다. 로딩 진행률은 뒤로 가지 않게 한다.

메뉴를 열 때는 기존 30종 총기, 원거리 무기 30종, 군인 4종, 식생 변형 9개, 정적 AO 394청크와 장전 데이터가 준비된다. v81의 네이티브 출력·해상도 설정·필터링을 유지한다.

## 반복 측정

| 조건 | 항목 | v81 | v82 | 단축 |
| --- | --- | ---: | ---: | ---: |
| 로컬 에셋 | 메뉴 준비 | 12.35초 | 11.04초 | 1.31초 / 10.6% |
| 로컬 에셋 | 첫 화면 완료 | 17.05초 | 16.07초 | 0.98초 / 5.8% |
| 스크립트 요청 지연 60ms | 메뉴 준비 | 18.43초 | 13.41초 | 5.03초 / 27.3% |
| 스크립트 요청 지연 60ms | 첫 화면 완료 | 23.29초 | 18.32초 | 4.97초 / 21.3% |

새 Chromium 컨텍스트에서 조건별 3회 중앙값을 사용한다. 로컬 HTTP 서버, CSS 800×450, DPR 1, 최저 품질, 같은 에셋과 장면이다. v81의 HTML과 전체 JS를 기준 커밋에 고정해 작업 파일을 되돌리지 않고 비교했다.

각 반복의 브라우저 컨텍스트는 새로 만들었지만, 초기 진단 후 OS 파일 캐시와 드라이버 캐시는 유지된 환경이다. 최초 장치 부팅이나 실제 사용자 환경에서 같은 단축률을 보장하는 수치는 아니다. 전후 12회 모두 동일한 에셋 준비 상태와 스크립트 단일 요청을 확인했다.

네트워크 지연 조건은 라이브러리·게임 스크립트 요청마다 60ms를 추가한 것이다. 전체 인터넷 대역폭이나 실제 사용자의 장치 성능을 재현하는 수치는 아니다. 첫 화면 완료는 프레임을 제출한 뒤 동기식 GPU 픽셀 읽기로 확인했다. 구간별 시간은 기다림을 포함하며, 겹친 구간을 단순 합산하면 안 된다.

## 검증

[로딩·복구 검사](v82-startup-checks.json) · [실행한 검사 목록](v82-checks.json)

로딩·화질·훈련장·훈련장 복구·번들 총기·네이티브 레티클 검사 **6종이 모두 통과**했다. 페이지·셰이더 오류는 없었다.

- M4 응답을 의도적으로 보류한 상태에서 맵 생성이 진행되는지 확인한다. 모델이 준비되기 전에는 로딩 창을 유지하고, 메뉴가 열린 직후 훈련장 진입과 실제 총기 렌더링을 확인한다.
- M4·Glock·나무 생성기 누락 시 기본 모델로 시작하고, 미처리 Promise 오류가 없는지 확인한다.
- `world.js` 누락 시 후속 스크립트 실행을 멈추고 한국어 오류를 표시하는지 확인한다.
- 기존 화질·에셋 복구, 훈련장·기본 모델 복구, 번들 모델·장전·조준경, 네이티브 레티클 검사를 실행한다.

```sh
node tools/check-startup.cjs
LOAD_RUNS=3 node tools/bench-startup.cjs before /tmp/lz-v82-startup
LOAD_RUNS=3 node tools/bench-startup.cjs after /tmp/lz-v82-startup
LOAD_RUNS=3 LOAD_LATENCY=60 node tools/bench-startup.cjs before /tmp/lz-v82-startup
LOAD_RUNS=3 LOAD_LATENCY=60 node tools/bench-startup.cjs after /tmp/lz-v82-startup
```

Playwright·Three.js·Chromium 경로는 기존 검사와 같은 `NODE_PATH`, `THREE_DIR`, `CHROME_BIN`을 사용한다. 제품 코드에 계측 후크를 넣지 않고 검사기에서만 적용한다. 새 로딩 검사를 GitHub Actions에 추가했다.

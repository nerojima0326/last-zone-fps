# v86 차량 바퀴·타이어 파손

기준은 v85 커밋 `401a95292dae33004113cb06264fcebba1934177`이다. Chromium 156 / Three.js r160 / SwiftShader에서 실제 게임과 탄도를 검사했다.

## 확인한 원인

포터 앞바퀴 반지름은 약 0.304m, 뒷바퀴는 약 0.249m인데 모든 바퀴가 같은 회전각을 사용했다. 앞바퀴는 물리의 속도별 조향각과 다른 고정 배율을 사용하고 핸드브레이크 중에도 뒷바퀴가 계속 굴렀다.

모델에도 문제가 있었다. 평평한 옆면 법선의 우세 방향을 확인하니 E2200의 앞바퀴는 약 **18.7도**, IZH는 약 **25도** 꺾인 자세가 정점에 구워져 있었다. 이를 그대로 차량 X축으로 돌려 바퀴가 비틀렸다. 기존 분리 과정은 바퀴 삼각형 일부를 차체에 남겨 회전·파손 후에도 고무 조각이 제자리에 보였다. 메시에 붙은 양자화 변환과 회전축을 구분할 필요도 있었다.

총탄은 차량 전체를 금속 차체로 처리했다. 특히 짧은 권총 탄도 구간은 타이어에 도달하기 전에 빈 휠하우스를 포함한 보행용 상자에 먼저 막혔다.

## 수정

- 실사 모델 3종에서 바퀴를 다시 분리하고 원본 조향 자세를 풀었다. 회전축을 별도 노드로 남겨 압축 변환이 축을 옮기지 않게 했다. 원본 텍스처·재질·삼각형 수는 보존한다. [모델 해시·원본 축·분리 기록](../../assets/models/vehicles/wheel-repair-v86.json).
- 바퀴별 실제 이동 거리와 반지름으로 굴린다. 후진에서는 반대로 돌고 정지 중에는 헛돌지 않는다. 안쪽 앞바퀴가 더 크게 꺾이는 조향을 적용하고 핸드브레이크를 당기면 뒷바퀴를 잠근다.
- 바퀴마다 내구도 36을 두고 차체 1,600과 분리했다. 조향·경사를 반영한 원통으로 타이어를 맞히고, 휠하우스에는 실제 차체 삼각형을 확인한다. 벽·차체·지붕이 앞에 있으면 타이어를 보호한다.
- 타이어가 파손되면 해당 차량의 고무 바깥 부분을 줄이고 림 중심부를 유지한다. 파열음·짧은 공기 소리·고무 파편과 먼지를 낸다. 접점과 차체 기울기를 보정하고 정차 차량의 충돌 상자도 갱신한다.
- 파손 개수에 따라 가속·전진·후진 속도와 접지력이 줄고 한쪽 파손 시 약하게 쏠린다. 운전 안내에 파손 개수를 표시한다. 차량이 재생성되면 정상 타이어로 돌아온다.
- 파손용 지오메트리는 파손 순간에만 복제한다. 차량 삭제·재생성 때 전용 지오메트리와 도장 재질을 정리한다. 새 차량·파손·폭발·장면 초기화 때 레이트레이싱 장면도 무효화해 변경을 반영하도록 했다.

## 검증

실사 모델 3종이 실제로 로드됐는지 확인하고 기본 대체 차량도 검사했다. 원본에 구워진 바퀴 축이 남지 않았는지 법선을 검사한 뒤, 굴림·후진·정지·안팎 조향·뒷바퀴 잠김을 확인했다. 모델 네 종류 × 총기 30종 **120개 조합**에서 실제 Ballistics를 통해 해당 타이어만 파손됐다. 근거리 AR-7은 두 발, 대구경 총은 한 발로 파손된다. 산탄총 검사에서 기록한 발수는 개별 펠릿을 뜻한다.

보정 후 평평한 옆면 법선에서 측정한 바퀴 축 편차는 모두 0.18도 이하였다. 차체에서 바퀴로 삼각형 1,184개를 옮겼으며 총 삼각형 수와 텍스처 바이트는 유지했다. 모델 세 개의 총 용량은 1,612,720바이트에서 1,516,480바이트로 약 6% 줄었다.

네 바퀴의 독립 파손, 파손 중복 방지, 벽·지붕의 가림, 기울어진 차체와 꺾인 바퀴 피격, 탑승 중 파손·안내, 파괴 후 재생성을 검사했다. 10초간 가속한 속도는 정상 21m/s, 한 바퀴 파손 17.85m/s, 두 바퀴 14.7m/s, 네 바퀴 8.4m/s였다.

모델을 모두 준비한 뒤 네 종류의 차량을 두 바퀴씩 파손·렌더·삭제하는 과정을 네 번 반복했다. 장면 객체·GPU 지오메트리·텍스처의 잔류 증가가 모두 0이었다. 기존 차체 내구도·화재·재생성, 훈련장 주행·경사 24조건·승하차, 총기·부착물 전투 검사도 실행했다.

[바퀴·탄도·리소스 검사](v86-wheels-checks.json) · [차량 생명주기 검사](v86-vehicle-vfx-checks.json) · [전후 캡처 기록](v86-comparison.json) · [실행한 검사 목록](v86-checks.json).

하드웨어 GPU의 FPS와 레이트레이싱 실기기는 이 환경에서 측정하지 않았다. 기존 품질 단계와 렌더 경로를 사용하며 지속적인 새 메시 생성이나 별도 후처리를 추가하지 않았다.

## 재현

```sh
node tools/check-vehicle-wheels.cjs
node tools/check-vehicle-throwable-vfx.cjs
node tools/check-training-range.cjs
node tools/check-combat.cjs
node tools/capture-vehicle-wheels.cjs before /tmp/lz-v86-evidence
WHEEL_ANIMATE=1 node tools/capture-vehicle-wheels.cjs after /tmp/lz-v86-evidence
```

기존 Playwright·Three.js·Chromium 설정을 사용하며 영상 저장에 ffmpeg가 필요하다. [모델 재생성](../../tools/vehicles/README.md)은 별도 도구와 고정 기준 커밋을 사용한다. 결과 GLB 3개와 매니페스트를 다시 생성해 동일한지 검사했다.
